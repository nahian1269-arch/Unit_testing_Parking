## B) Defects list

These six defects are reported from the checked-in tests and implementation. D-01, D-02, D-04, D-05, and D-06 have active regression tests that currently fail against the implementation. D-03 has an active test documenting that LARGE currently rejects TRUCK; the expected compatibility rule should be confirmed against the assignment specification.

| Defect ID | Class.Method | Description | Suggested fix |
|---|---|---|---|
| D-01 | `Booking.cancelBooking()` | A completed booking can be cancelled because there is no status validation. The active test expects a completed booking to remain completed, but currently fails. | Reject cancellation when status is `COMPLETED`, for example by throwing `IllegalStateException`, and cover the chosen rejection behavior. |
| D-02 | `Booking.Booking()` | The constructor accepts equal (and reversed) start/end times, allowing invalid booking objects. The active equal-time test currently fails. | Validate `endTime.isAfter(startTime)` in the constructor and throw the project's booking-time exception (or another documented exception). |
| D-03 | `ParkingSlot.isCompatible()` | No `TRUCK` branch exists, so TRUCK is incompatible with every slot, including LARGE. The active test asserts this current behavior; intended compatibility is inferred from the existing truck rate and should be checked against the assignment matrix. | Add `case TRUCK` with LARGE compatibility if that is the intended matrix, and change/add a test to assert the intended positive behavior. |
| D-04 | `ParkingSystem.book()` | `Duration.toHours()` truncates partial hours. For 30 minutes the fare becomes 0.0, then the zero transfer is rejected by `Wallet.addFunds()` with `InvalidAmountException`. The active partial-hour test currently errors before its fare assertion. | Calculate fractional hours (such as minutes divided by `60.0`) or use the documented rounding rule; test both amount and successful payment. |
| D-05 | `ParkingSystem.book()` | The system booking is appended before payment transfer. If the customer has insufficient funds, payment fails but the booking remains in the system list. The active regression test currently fails its empty-list assertion. | Ensure payment succeeds before committing system/slot booking state; verify all relevant state is unchanged on failure. |
| D-06 | `ParkingSystem.completeBooking()` | Repeated completion transfers the slot share repeatedly. The active regression test currently observes 32.0 instead of 16.0. | Only settle an `ACTIVE` booking once; reject or safely ignore subsequent completion and test repeated calls. |
